★ **Revised 2026-10-01 on the owner's comment — read by default, edit on intent.** The profile is

Edit mode (`MeEdit.dc.html`, entered only by that button): the header reads «تعديل ملفي» · the fields (`profile.*`), a **changed field bordered accent** (the count in the header is the only text about it) · sticky

read mode. Save → read mode, `profile.saved` once; leaving with unsaved changes asks.

### The principle (`DEC-NEXT-23`, §10) — applies to anything editable in the app

1. **Values, not inputs, until the person asks to edit.** A screen that holds settings or a profile
   renders them as a list of label/value rows with one «عدّل» control; an input exists only in edit
   mode. Forms whose purpose is entry (`017` propose, `015` rate, `014` check-in) are forms; a
   screen whose purpose is to *hold* values is not.
2. **Edit mode names its state**: a header that says it is editing, the count of unsaved changes,
   each changed field marked by its accent border, a Save that names the count and a
   Cancel that restores. Nothing is written until Save; leaving with changes asks.
3. **Saved is shown, not assumed**: the `status-mark` ✓✓ «محفوظ» with the last-edit time in read
   mode, and `saved` once after a save. Autosaved drafts (`017`) show ○→✓✓ «مسودة محفوظة قبل …»
   the same way; per-toggle saves (`026` preferences) flash the mark beside the switch.

Retrofit: `029`'s switches keep their form (a toggle is its own edit intent);
`018`'s co-presenter management and the console's settings pages follow this principle in their
batches. States for `021`: **no company** (`app.home.companyMissing` banner, the row says
«اختر شركتك» as the edit link) · **errors** (`profile.errors.summaryTitle`, `form-summary`, edit mode
stays) · **saved** (`profile.saved` toast once). **Moments 3 and 5 live on the standing card**
(`DEC-195`; `DEC-213` §5.117 keeps the level-up off the profile).

## 5. SCR-025 التقويم · `Calendar.dc.html`

★ **Reworked 2026-10-01 — the principle, not a glyph set.** The calendar shows the member's
sessions; this page does not repeat them. It holds exactly two things: **the connection** (one row:
«تقويم Google · متصل · افصل»; disconnected: the row says «غير متصل» and the control is «اربط») and
**what needs a hand** — a «لم تُضف» list of sessions that failed to reach the calendar, each with
«أعد المحاولة». When nothing failed, the page is the one row. No synced list, no legend, no marks.
It is reachable from the settings row «تقويم Google»; the hub strip keeps «التقويم» for now (the
lead may fold it into `029` if the owner prefers — proposed in §10).

### The principle (`DEC-NEXT-22`, replaces the earlier glyph vocabulary)

State lives in the row itself: the badge the row already has (`011`'s), a dimmed row, a struck
title, a word. **Nothing is shown when nothing needs doing** — a healthy integration is one row,
a synced session is absent, a saved form says nothing. A glyph is never a vocabulary the person has
to learn. The `status-mark` primitive is **withdrawn**.

- **`DEC-NEXT-19` — the weekly window is a board tab.** `09` names الكل · هذا الشهر · حسب التصنيف ·
  سباق الشركات; the questionnaire added **weekly, monthly, all-time** with the weekly as the headline

- **`DEC-NEXT-21` — the reversal pair is one card.** `05` lists reversals as rows; the design shows

  names the standing card as where they render on `/app/me`). No sixth moment; the podium does not
  animate.
- **`DEC-NEXT-22` — state lives in the row; nothing is shown when nothing needs doing.** Owner's
  rulings of 2026-10-01 (§5). A healthy integration is one row; a synced session is absent; a saved
  form says nothing. No glyph vocabulary. Open to the owner: fold `025` into `029`'s row entirely.
- **`DEC-NEXT-23` — read by default, edit on intent.** Owner's comment, 2026-10-01: a screen that
  holds values renders values with one edit control; edit mode names its state and its unsaved
  count; saved is shown with the `status-mark`. §1 has the three rules and the retrofit list.
- **`DEC-NEXT-24` — `/app/me/settings` is a route**, and notification preferences, leaderboard

  put preferences on `026` and the opt-out on `021`; the owner's comment of 2026-10-01 moves both.

  next; facts live in one place (the empty state, the error) and never as hints, legends or footnotes.
